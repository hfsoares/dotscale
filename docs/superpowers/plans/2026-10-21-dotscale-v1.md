# DotScale v1 — Plano de implementação

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** App Flutter (Android agora, iOS depois) que conecta na Timemore Dot por BLE e mostra peso, fluxo e bateria ao vivo, com painel de debug dos frames crus.

**Architecture:** Três camadas com dependência num sentido só:

1. `lib/protocol/`: Dart puro, sem Flutter. Contém CRC, montagem de comandos, remontagem do stream e decodificação.
2. `lib/ble/`: implementa a interface `ScaleConnection` sobre o `flutter_blue_plus`.
3. `lib/ui/`: um `ScaleController` (ChangeNotifier) consome a `ScaleConnection`, e os widgets leem o controller.

A UI é testada com uma `ScaleConnection` falsa.

**Tech Stack:** Flutter (canal stable), Dart 3, `flutter_blue_plus`, `shared_preferences`, `wakelock_plus`, `flutter_test`. Build Android com o JDK 21 do sistema.

**Spec:** `docs/superpowers/specs/2026-10-21-dotscale-v1-design.md`

## Global Constraints

**Ambiente**
- JDK: `/usr/lib/jvm/java-21-openjdk-amd64`. Não usar o JDK 11, que é o padrão do sistema.
- Android SDK em `~/Android/Sdk`, Flutter SDK em `~/development/flutter`. Ambos instalados pela linha de comando, sem Android Studio.
- Projeto Flutter na raiz do repositório `/home/humberto/pessoal/dotscale`, nome `dotscale`, org `com.humberto`, plataformas `android,ios`.

**Protocolo**
- Serviço `0000fff0-0000-1000-8000-00805f9b34fb`.
- Notificações em `0000fff1-...`, comandos em `0000fff2-...`. Comandos são enviados como write **without** response.
- Frame: `A5 5A | classe | tipo | len(2, BE) | payload | CRC(2, BE)`.
- CRC-16/MODBUS: init `0xFFFF`, poly refletido `0xA001`, calculado sobre todos os bytes anteriores.
- O CRC de entrada **não** derruba frames: só marca `crcOk=false`.
- Payload maior que 64 bytes significa dessincronização: descartar o byte e ressincronizar.
- Dot reconhecida pelo nome: começa com `TIMEMORE_Dot` ou contém `tes017`, sem diferenciar maiúsculas.

**Ao conectar**
1. Garantir bond no Android (`createBond`). No iOS o sistema pareia sozinho.
2. Assinar FFF1.
3. Esperar 500 ms e enviar unidade gramas `03 06 [00]`.
4. Esperar 200 ms e enviar modo padrão `03 08 [01 00]`.

Nunca tarar na conexão. Sem keep-alive. Nunca usar `02 04` como tara (é uma consulta).

**Permissões**
- Android 12+: `BLUETOOTH_SCAN` (com `neverForLocation`) e `BLUETOOTH_CONNECT`.
- Android ≤ 11: `ACCESS_FINE_LOCATION` e as permissões `BLUETOOTH`/`BLUETOOTH_ADMIN` com `maxSdkVersion="30"`.
- iOS: `NSBluetoothAlwaysUsageDescription`.

**Interface**
- Textos em português.
- Peso com uma casa decimal e `g`. Fluxo com uma casa e `g/s`. Bateria em `%`.
- Tela sempre ligada só enquanto conectado.
- Lembrar o id da última balança e tentar reconectar a ela ao abrir o app.

## Review Focus

1. **Bluetooth desligado ou permissão negada:** a tela diz o que está errado e oferece "Tentar de novo". Nada de travar ou de mostrar uma lista vazia em silêncio. Testado na Task 5.
2. **Balança desligada no meio do uso:** o último peso não pode continuar parecendo ao vivo. A tela mostra "Reconectando…" e o peso fica esmaecido. Testado na Task 5.
3. **Pareamento recusado ou falho:** a tela mostra o erro e um botão para tentar de novo. Não fica presa em "Conectando…". Testado na Task 5.
4. **Peso acima de 3276,7 g** (por exemplo, um jarro grande): o valor deve vir certo, o que exige ler int32 e não int16 (o de1app erra nisso). Testado na Task 3.
5. **Ruído perto de zero:** um valor entre −0,05 e 0 não pode aparecer como "-0.0 g". Testado na Task 5.

### Task 3: Decodificador de stream e eventos

**Files:**
- Create: `lib/protocol/dot_event.dart`, `lib/protocol/frame_decoder.dart`
- Test: `test/protocol/frame_decoder_test.dart`

**Interfaces:**
- Consumes: `crc16Modbus` e as constantes da Task 2.
- Produces:
  ```dart
  sealed class DotEvent {}
  final class WeightReading extends DotEvent { final double grams; final double flowGramsPerSecond; final int timerSeconds; final bool overload; }
  final class BatteryReading extends DotEvent { final int percent; }
  final class UnknownReport extends DotEvent { final int frameClass; final int type; final List<int> payload; }

  class DecodedFrame { final Uint8List bytes; final int frameClass; final int type; final Uint8List payload; final bool crcOk; final DotEvent? event; }

  class FrameDecoder {
    List<DecodedFrame> add(List<int> chunk); // devolve 0..n frames completos
    void reset();
  }
  ```

**Regras do evento:**
- `event` só existe para as classes 0x01 e 0x02. Frames de classe 0x03 (ACK de comando) ficam com `event == null`.
- `WeightReading` exige tipo 0x01 e payload ≥ 8 bytes:
  - `grams` = int32 com sinal (BE) de `payload[0..3]` / 10;
  - `flowGramsPerSecond` = int16 com sinal de `payload[4..5]` / 10;
  - `timerSeconds` = uint16 de `payload[6..7]`;
  - `overload` = `payload[8] != 0`, ou `false` se o payload tiver só 8 bytes.
- `BatteryReading` exige tipo 0x05 e payload ≥ 2 bytes. `percent` = `payload[1]`.
- Qualquer outra combinação vira `UnknownReport`.

Nos testes, use um helper `weightFrame(int raw, {int flow = 0, int timer = 0, int overload = 0})` que monta o frame via `buildFrame(kClassNotify, kTypeWeight, ...)`.

- [ ] **Step 1: Escrever os testes que falham**
  - `frame inteiro de peso`: raw 184 → um frame, `grams == 18.4`, `crcOk == true`.
  - `peso negativo`: raw -25 → `grams == -2.5`.
  - `peso acima de 3276.7 g`: raw 45000 → `grams == 4500.0` (Review Focus 4).
  - `fluxo negativo e timer`: flow -12, timer 65 → `flowGramsPerSecond == -1.2`, `timerSeconds == 65`.
  - `frame dividido em 3 pedaços`: as duas primeiras chamadas de `add` devolvem `[]` e a terceira devolve 1 frame.
  - `dois frames na mesma notificação`: uma chamada devolve 2 frames, na ordem.
  - `lixo antes do magic`: `[0x00, 0x13, 0xA5]` + frame → devolve exatamente 1 frame válido.
  - `A5 sem 5A é descartado`: `[0xA5, 0x00]` + frame → 1 frame.
  - `tamanho absurdo ressincroniza`: `[0xA5,0x5A,0x01,0x01,0x01,0x00]` (len 256) seguido de um frame válido → devolve o frame válido.
  - `CRC divergente não derruba`: frame com o último byte alterado → 1 frame, `crcOk == false`, `event` ainda é `WeightReading`.
  - `bateria`: `buildFrame(1, 5, [0x02, 87])` → `BatteryReading(percent: 87)`.
  - `classe 0x02 também é relatório`: frame de peso com classe 0x02 → `WeightReading`.
  - `ACK de comando sem evento`: `buildFrame(3, 0x0D, [1])` → `event == null`.
  - `tipo desconhecido`: `buildFrame(1, 0x10, [1,2])` → `UnknownReport` com type 0x10.
- [ ] **Step 2: Rodar e confirmar a falha.** `flutter test test/protocol/frame_decoder_test.dart`. Esperado: FAIL.
- [ ] **Step 3: Implementar** `FrameDecoder` com um buffer interno. Em cada `add`, repetir até não haver frame completo:
  1. Descartar bytes até o próximo `0xA5`.
  2. Se houver menos de 8 bytes, parar e esperar mais dados.
  3. Se o segundo byte não for `0x5A`, ou se len > 64: descartar 1 byte e continuar.
  4. Se o frame ainda não estiver inteiro, parar e esperar.
  5. Senão, extrair o frame, conferir o CRC e decodificar o evento.
- [ ] **Step 4: Rodar e confirmar que passa.** O mesmo comando dá PASS.
